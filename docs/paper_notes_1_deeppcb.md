## 1. 研究背景与动机

### 1.1 传统方法的三个痛点

早期 PCB 缺陷检测以**图像差分 + 图像处理**为主（小波方法、形态学分割、减影 + KNN、连通域分析等）。论文归纳这类方法失效的三种情形：

1. **复杂/未定义的缺陷模式**：靠"逻辑推理"判断差异区域的传统规则覆盖不了所有真实缺陷形态；
2. **模板图与待检图之间的不规则形变和偏移**：差分对配准误差极其敏感；
3. **超参数过敏感**：如腐蚀/膨胀核大小等，换个产线/板型就要重调。

### 1.2 为什么用深度学习、难点在哪

作者把 PCB 缺陷检测视为目标检测任务，但指出与通用目标检测有两点差别：

1. 检测对象是 PCB 缺陷（小目标、类别语义特殊）；
2. **输入是成对图像**（template + tested）——这是该任务区别于普通检测的核心特征。

深度模型的矛盾：高精度要深网络/大感受野，高效率要轻量化。这直接引出 GPP 模块的设计动机。

## 2. DeepPCB 数据集（重点）

### 2.1 构建流程（论文 §2.1）

```
整板扫描（线阵 CCD，约 48 px/mm，原始约 16k×16k 像素）
   ↓ 人工检查并清洗出无缺陷模板图
裁剪成 640×640 子图
   ↓ 模板匹配对齐（消除平移和旋转偏移）
阈值二值化（消除光照扰动）
   ↓ 人工按 PCB 缺陷模式在待检图上"增补"人工缺陷
标注（轴对齐框 + 类别 ID）
```

要点解读：

- **数据是真实工业成像**（线阵 CCD），但**二值化后的图像是"理想化"的**——黑白两色、无噪声。这是 DeepPCB 最常被后续论文批评的点：在它上面训练的模型对真实含噪图像的泛化性存疑（对比论文二的 DsPCBSD+ 正是针对这一点做的真实数据集）。
- **人工增补缺陷**：真实待检图缺陷很少（一张整板裁出的子图可能没缺陷），作者按缺陷模式人工合成/移植缺陷到图上，使每图约 3~12 个缺陷。即"真实图像 + 人工缺陷"的混合构建方式。
- **对齐已做好**：数据集自带模板匹配对齐结果，使用者不必再做配准——这大幅降低了使用门槛，也是 demo 中可直接做 `absdiff` 差分的原因。

### 2.3 评估协议（论文 §2.3，重点）

- 指标：**AP（average precision）** 与 **F-mean（F-score）**，参照 PASCAL VOC 与 ICDAR2015 的做法；
- 命中判定：检测框与**同类别** GT 框 **IoU > 0.33** 才算正确（远低于通用 0.5，因为缺陷框很小）；
- F-score 阈值敏感，部署时必给阈值，故与 mAP 并列报告；
- 官方开源了配套评估脚本（改自 ICDAR2015 RRC，**Python 2**）和测试集 `gt.zip`。

> 本会话已实测验证：`evaluation/gt.zip`（500 个 txt，3,140 框）与 `PCBData/test.txt` 指向的标注**逐框一致**，说明官方测试集划分未变，我们的 demo 可以直接对齐官方协议。

## 3. 方法：GPP 检测模型（论文 §3）

### 3.1 整体结构（论文 Fig.3）

```
template图 ─→ 共享参数的卷积backbone（VGG16-tiny 或 ResNet18 去掉FC）─┐
                                                                      ├→ 特征相减（feature subtraction）
tested图  ─→ 共享参数的卷积backbone ────────────────────────────────┘
                                  ↓
                        Group Pyramid Pooling (GPP)
                                  ↓
              每组 → Conv3×3×(3×(classes+4)) → 预测不同尺度的框
                                  ↓
                              NMS → 最终结果
```

设计取舍解读：

- **不做像素差分、做特征差分**：先过卷积 backbone 提取具有平移/旋转不变性的特征再相减，天然对配准残差更鲁棒（回应 §1.1 痛点 2）；
- backbone 双分支**共享参数**（同一种"正常线路"的表征）。

### 3.2 GPP 模块细节

- 从 backbone 特征图做 6 种池化：**2×2、4×4、6×6、12×12、18×18、24×24**（消融中还出现 1×1），每种池化后接 `Conv1×1 → BN → ReLU → 上采样（双线性插值）`，再按组 Concatenate；
- **分组**（论文示例）：
  - 第 1 组：{1×1, 2×2, 4×4} → 预测**小框**；
  - 中间组：{4×4, 6×6, 12×12} → 预测**中框**；
  - 第 3 组：{12×12, 18×18, 24×24} → 预测**大框**；
- 相邻组**共享部分池化输入**（如 4×4、12×12 同时出现在两组），以减少分组带来的边缘效应；
- 与 FPN 的区别：FPN 自底向上逐级融合（计算/显存开销大），GPP 用金字塔池化一次性拿到多分辨率特征，更轻；
- 与 PSPNet 的关系：金字塔池化思想来自 PSPNet，但 GPP **分组且组间重叠**，每组对应一个尺度范围的 default box 预测。

### 3.3 预测头与先验框

- 每组特征图经 `Conv 3×3×(3×(classes+4))` 输出：每个空间位置 3 个 default box（SSD 风格）；
- default box 长宽比 **0.5 / 1.0 / 2.0**，尺寸取输入图像的 **0.04 / 0.08 / 0.16**（对应小/中/大框；640 输入下即约 25.6 / 51.2 / 102.4 像素——印证了"缺陷多为小目标"）；
- 每个位置输出：7 类概率（6 缺陷 + background）+ 4 个回归量（中心偏移 + 宽高缩放比）；
- 各尺度预测汇总后做 **NMS**。

### 3.4 损失函数（SSD 式）

- **匹配**：每个 GT 框先匹配 Jaccard 重叠最大的 default box；再把 Jaccard > 0.5 的 default box 都算匹配上；
- **回归损失**：smooth L1，目标偏移按 default box 尺寸归一化：
  - 中心：`t = (g − d) / d`；宽高：`t = log(g / d)`；
- **分类损失**：softmax 交叉熵；背景/前景 default box 比例控制在约 **3 : 1**（SSD 的难例/负采样思路的简化版）。

### 3.5 训练配置（复现参考）

| 项 | 设置 |
|---|---|
| 硬件 | 单卡 Titan X |
| 优化器 | Adam，初始 lr 1e-3，weight decay 5e-4 |
| 训练量 | 500 epochs，batch size 16，lr 每 100 epoch ×0.33 |
| 耗时 | 约 0.5 天 |
| 数据增强 | 模板/待检图**同步**随机水平/垂直翻转（p=0.5，图对必须同变换），随机裁剪至 512×512 |

## 4. 实验结果（论文 §4）

### 4.1 主结果：mAP（%，测试集 500 张）

| 方法 | mAP | open | short | mousebite | spur | copper | pin-hole |
|---|---|---|---|---|---|---|---|
| 图像处理（形态学）[2] | 89.3 | 88.2 | 87.6 | 90.3 | 88.9 | 91.5 | 89.2 |
| YOLO (v1) | 92.6 | 90.5 | 92.0 | 93.1 | 93.3 | 94.9 | 92.6 |
| SSD | 95.9 | 93.1 | 94.5 | 95.7 | 96.7 | 96.9 | 98.7 |
| Faster R-CNN | 97.6 | 96.8 | 95.4 | 97.9 | 98.7 | 97.4 | 99.5 |
| ours-AP（GPP 用平均池化） | 97.1 | 97.0 | 93.5 | 98.7 | 96.6 | 97.4 | 99.9 |
| **ours-MP（GPP 用最大池化）** | **98.6** | 98.5 | 98.5 | 99.1 | 98.2 | 98.5 | 99.4 |

> 对比方法也统一改为"backbone 双分支 + 特征相减"的成对输入方式，保证公平。

### 4.2 速度-精度权衡（论文 Fig.4，F-score @ FPS）

| 方法 | F-score | FPS |
|---|---|---|
| 图像处理 [2] | 89.8 | 78 |
| YOLO | 93.1 | 34 |
| SSD | 95.4 | 64 |
| Faster R-CNN | 97.8 | **4** |
| **ours (MP)** | **98.2** | **62** |

结论：GPP 模型是精度-速度 Pareto 前沿上唯一同时达到 98+ / 60+ 的方法。

### 4.3 消融实验（F-score）

| 设置 | precision | recall | F-mean | 说明 |
|---|---|---|---|---|
| SSD-FPN（同 backbone，改用 FPN 融合） | 94.9 | 96.8 | 95.8 | FPN 替代方案 |
| ours-non-GPP（只留 1×1/4×4/12×12 池化） | 94.3 | 96.3 | 95.3 | 去掉分组重叠 |
| **ours-MP（完整 GPP）** | **98.2** | 98.1 | **98.2** | |

两个结论：① GPP 完整分组结构比"稀疏池化"高 **3.9%**，比 SSD-FPN 高 **3.3%**；② 最大池化比平均池化高 **1.5% mAP**（缺陷是二值图上的细小结构，max 更能保留突变特征）。

## 5. 批判性评价

**优点**
- 首个公开 PCB 缺陷检测数据集，构建流程（扫描→对齐→二值化→标注）有完整交代，评估协议明确可复现；
- GPP 结构轻量、思想清晰（分组金字塔 + 组间重叠 + 各组负责一个尺度），消融充分；
- 同时报告 mAP 与 F-score@FPS，兼顾学术指标与落地指标。

**局限（做 demo / 写 README 时值得引用的讨论点）**
1. **图像过度理想化**：二值化消除了噪声、纹理、光照，真实 AOI 场景远比这复杂（这正是论文二 DsPCBSD+ 的出发点）；
2. **人工合成缺陷**：约 3~12 个/图的缺陷多为人工增补，类内多样性有限；
3. 论文模型代码未开源，98.6% mAP 无人能直接复现，后续工作的对比都基于数据集协议而非原模型；
4. IoU 0.33 的宽松判定标准使 mAP 普遍偏高，跨数据集比较时要注意；
5. 论文 Fig.2 统计与仓库实际数据不一致（见 §2.2），引用数字时需谨慎。

## 6. 对我们 demo 项目的直接指导

1. **输入形态**：demo 的模型输入应是 `test 图`（单图检测路线，如 YOLOv8），或实现"模板特征差分"作为附加路线（`cv2.absdiff` 传统基线 + 双分支网络进阶版）；
2. **评估协议**：写一个 Python3 评估器，严格对齐"同类 IoU>0.33 + mAP + F-score"，与 `gt.zip`/`test.txt` 划分保持一致，结果才能与论文表格直接可比；
3. **benchmark 预期**：论文中 SSD 95.9 / Faster 97.6 / 自研 98.6——现代 YOLOv8/v11 在该数据集上通常能到 98%+ mAP，demo 达到 95%+ 即可作为成功的演示点；
4. **先验框尺度参考**：default box 0.04/0.08/0.16（约 26/51/102 像素）说明缺陷以小目标为主——YOLO 训练时 imgsz=640 起步、必要时开 P2 检测头；
5. **增强注意**：若使用模板-待检成对输入，翻转/裁剪等增强必须对图对**同步**施加；
